## 产品背景

`NEP Dataset Display / Show NEP` 已经可以：

- 浏览单个结构和误差散点。
- 搜索、圈选、按范围选择结构。
- 标记 reject、删除、撤销和导出。
- 查看最大误差、运行 FPS 和探索数值分布。

Audit 不应该复制这些操作。它需要弥补 Show NEP 的不足：

> 把整个训练集压缩成用户能理解、能追溯、能采取行动的结论，帮助用户查缺补漏并判断下一步方向。

用户通常不能在打开页面前完整表达温度、压力、相、缺陷和目标物性。因此页面不能强迫用户先完成一个复杂目标向导。即使没有目标和模型，也应该先给出有价值的数据盘点；随后再渐进加入目标和模型证据。

## 必须解决的用户问题

默认首屏需要在不理解算法名词的情况下回答：

1. 当前检查的是哪些数据？
2. 我的数据集里有什么？
3. 纯元素和主要组成分别有多少？
4. 数据集中在哪些组成、结构类型或来源？
5. 有没有明确的数据质量阻塞？
6. 哪些结构组值得人工复核？
7. 我现在最值得先做哪三件事？
8. 哪些结论因为缺少目标或模型而暂时无法判断？

有目标后才回答：

- 目标组成、结构家族或目标数据中哪些区域有支持、偏薄或没有样本。

有参考值和预测值后才回答：

- 模型误差集中在哪些组成、结构家族、元素或局域环境。

## 需要你重点判断的设计问题

请不要默认接受下面的方案，而是比较后作出明确选择：

### 1. 页面入口

比较：

- 打开后先选择“快速体检 / 目标覆盖 / 模型验收”三种模式。
- 打开后直接展示数据盘点，再渐进启用目标和模型区域。

当前倾向第二种，因为用户经常说不清目标，但请从真实使用路径判断是否正确。

### 2. 信息架构

当前候选结构是：

- 概览。
- 数据地图。
- 复核队列。
- 目标与模型。
- 高级证据。

请判断是否过多、是否应合并，并给出最终导航。

### 3. 首页结论

首页应该优先显示：

- 数据盘点。
- 数据阻塞。
- 最显著的采样事实。
- 下一步动作。

Composition、Label ranges、Local chemistry、Pair contacts 和 Distribution 是否应该全部下降到证据层？请明确判断。

### 4. “偏聚”语义

必须区分：

- 数据集样本集中在少数组成点。
- 单个结构内部的元素偏聚或短程有序。

前者属于组成盘点；后者需要按组成和结构类型分层的局域化学/SRO 分析。不要把原始元素对接触数直接叫作偏聚。

### 5. 下一步建议

没有目标时，软件不能直接说“补纯 Ni”或“补某组成”。它可以说：

- 确认某个组成占比是否符合预期。
- 查看纯端元的结构来源。
- 设置关注的组成范围以判断真正缺口。

请设计既有帮助、又不越过证据边界的动作语言。

## UI 视觉要求

- 这是科研桌面软件，不是商业 BI 仪表盘或营销网站。
- 延续 NepTrainKit / qfluentwidgets 的清爽桌面风格。
- 优先浅色主题；可以附带一张深色适配示意，但不是必需。
- 建议画布为 1440×900 或接近比例。
- 中文界面文案，科学单位和元素符号保持规范。
- 首屏信息必须在一屏内读完，不依赖滚动才能知道结论。
- 避免大面积渐变、发光、玻璃拟态、装饰性大图标和过多彩色 KPI 卡。
- 风险颜色仅用于明确 blocker；普通采样事实使用中性色。
- 图表必须服务于一个明确问题。
- 组成图需要显示精确组成点，纯 Fe/纯 Ni 端点固定可见。
- 每个重要事实都要有明确的主动作，例如“查看 28,746 个结构”。
