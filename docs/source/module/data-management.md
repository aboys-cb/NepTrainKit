# 数据管理（Data Management）

`数据管理` 用来记录项目、模型版本、数据路径和备注。它不负责生成结构，也不负责训练；
它解决的是另一个问题：当你有很多轮 DFT、很多个 `nep.txt`、很多个候选池和训练结果时，
还能知道每个文件属于哪一次实验。

## 什么时候值得用

下面这些情况建议开始记录：

- 同一个材料体系已经做了多轮主动学习。
- 每一轮都有候选结构、清洗结构、DFT 结果、训练模型和测试结果。
- 你需要对比不同 `nep.txt` 的误差、备注和适用范围。
- 你经常回头找“上次那个效果好的模型在哪个目录”。

如果只是临时试一张卡片，不一定需要马上建项目。

## 推荐记录方式

可以按材料体系或研究主题建立 `Project`，再把每一轮模型作为 `Model(version)` 记录进去。

一个常见结构是：

```text
Project: TiH2 surface defects
  v001: 初始 bulk + surface 数据
  v002: 加入 vacancy / adsorbate 候选结构
  v003: 清洗后 FPS 采样并完成 DFT
  v004: 回看训练误差后补高力结构
```

每个版本建议至少记录：

- 模型或结果目录路径。
- 对应的训练集来源。
- 简短备注：这一轮补了什么结构、删了什么异常、模型适合什么范围。
- 标签：例如 `surface`、`defect`、`magnetic`、`failed`、`baseline`。

## 和主流程的关系

`数据管理` 更适合放在每轮流程结束后使用：

```text
构建数据集：生成候选结构
-> NEP 数据集查看：清洗
-> DFT
-> GPUMD 训练
-> NEP 数据集查看：回看
-> Data Management 记录这一轮
```

这样记录的是已经有明确意义的版本，而不是每个临时文件。

## 常用操作

- 新建、修改、删除 `Project`。
- 新建、修改、删除 `Model(version)`。
- 打开本地目录或 URL。
- 用 `Ctrl+F` 搜索项目、标签、备注或路径。

### 拖拽导入 NEP 模型

将 `.txt` 模型文件或包含模型的文件夹拖入数据管理页。软件根据 NEP 文件头识别模型，不要求文件一定名为 `nep.txt`；文件夹优先采用其中有效的 `nep.txt`，否则检查该文件夹直接包含的其他 `.txt`，不递归扫描子目录。普通说明文本不会作为模型导入。

识别成功后弹出导入窗口，自动填入模型名称，并显示实际文件路径、模型类型和元素。项目优先沿用当前选择，其次沿用上次保存的项目，没有时预填 `Inbox`；项目和名称都可以修改。单个有效候选只需确认一次；多个候选在同一窗口中选择，再点“导入”。取消不会创建项目或模型快照。

导入保存窗口中预览过的模型权重快照，不要求提供 `train.xyz`。同目录的 `energy_*.out`、`force_*.out`、`virial_*.out`、`mforce_*.out` 会在后台分块读取并自动填入 RMSE；不会重新运行模型预测。训练 / 测试输出分组显示，可在导入前选择，缺失项显示为不可用。没有来源哈希时标为“历史精度，未校验”；已知模型或输出哈希不符时仅导入权重。完整来源记录及本地数据均通过校验时才标为已校验。磁力及各项有效分量数随导入记录保存；历史统计不替代模型验证页的评估记录。数据集可以随后另行选择并运行评估。识别文件头不等于完整模型可计算。

删除项目只删除该项目及其子项目拥有的模型。其他项目的派生版本会保留，并解除指向已删版本的父关系；指向这些保留版本的基准选择和评估记录不受影响。修改项目归属或标签后，当前列表会自动刷新。

验证集导入会核对已确认预览的文件内容。大文件确认期间文件发生变化时，需要重新加载预览。新建验证方案及其成员、目录批量导入各自作为完整事务提交，失败时数据库记录整体回滚，不留下阻止重试的空方案或部分目录。

### 单独选择数据并计算精度

1. 用“新建模型”选择 `.txt` 权重，或拖拽文件 / 文件夹导入模型；无需同目录的训练数据和输出。
2. 切换到模型验证，导入参考数据，选择“能量 / 力 / virial 误差”，独立选择带标签的 EXTXYZ，并加入一个验证方案。
3. 选择当前模型和要比较的模型，勾选要评估的验证项，核对模型数、验证项数和任务数，再运行验证。每个模型在同一封存数据上独立调用 NEPAdapters。
4. 运行菜单中的“重新计算所选模型”会绕过已有评估记录。普通运行只复用模型、数据、评估协议及运行环境匹配的成功记录。

每条评估记录显式保存模型与数据的 SHA-256。结果明细保存零基帧索引、逐帧原子数、评估来源及各项标签数量；EOS 分组使用原文件中的帧索引。范围中的原子指各项参考标签实际覆盖的原子，不根据磁矩是否为零自动筛选。

| 项目 | 参考值与显示单位 | 有效数量 |
|---|---|---|
| 能量 E | 输入总能量 eV，按原子数归一后显示 meV/atom | 有标签的结构数、对应原子数和标量数 |
| 原子力 F | 输入 eV/Å，显示 meV/Å | 有标签的结构数、原子数和三维分量数 |
| Virial V | 输入总 virial eV，按原子数归一后显示 meV/atom | 有标签的结构数及六分量数 |
| 磁力 MF | 读取 `force_mag` 或 `mforce`，输入 eV/μB，显示 meV/μB | 有标签的结构数、原子数和三维分量数 |

各项独立统计：一帧没有力标签，不影响其他帧的力误差；没有能量但有力或磁力标签的数据也可评估。未标注项不参与 RMSE/MAE，不会补零或把预测值当参考；真实零标签会计入。已经提供却包含 NaN/Inf、形状错误或相互冲突的标签会报错，非有限预测也会失败。

结果同时记录有效参考分量数和实际比较分量数。不输出磁力的模型会将磁力误差显示为不可用、比较数量记为零，其他有参考标签的量仍可比较。磁力采用模型和标签共同约定的磁矩导数，不自动转换为力矩或改变自旋归一化。

RMSE 和 MAE 按有效分量平均。精度协议 v2 的 virial 固定采用 NEP 六分量顺序 `xx, yy, zz, xy, yz, zx`，与官方 `.out` 一致；不会把非对角元重复计权。旧 v1 九分量误差记录保留，但不会作为 v2 结果复用；旧分享包中的参考数据可重新导入并按 v2 评估。

### 导入已有输出缓存

在运行菜单选择“为精度数据导入 .out 缓存”，选取包含 `prediction.meta.json` 和对应输出的文件夹。该操作只针对当前范围内所选模型的精度数据集，不用于 EOS 拟合或无参考诊断。

正式复用缓存须核对模型哈希、数据哈希、结构数、原子数、每个所需输出文件的 SHA-256、数组形状及有标签位置的参考列。能量、力、virial、磁力分别读取 `energy_*.out`、`force_*.out`、`virial_*.out`、`mforce_*.out`，缺失参考位置仍以所选数据的标签掩码为准。

新生成的结果页缓存会保存输出文件哈希。旧 `.out` 没有来源记录或输出哈希、文件被替换、参考列错位时，会保留原文件并调用 NEPAdapters 重算，原因写入评估记录和详情。后端无法计算时显示失败，不会登记为零误差；仅凭文件名、行数或同目录关系不能确认旧输出来自当前权重。

项目编辑窗口中的历史手填 RMSE 标为“未校验”，不再扫描同目录 `.out` 自动填写，也不作为上述带哈希评估记录使用。选择了某个数据集只表明评估覆盖该数据，文件名或低 RMSE 不会自动证明它是独立留出集或模型具有外推能力。

EOS 曲线始终使用紧凑图卡，单组或聚焦某组时也不会铺满窗口；多组按窗口宽度排列。空间足够显示单组时不会额外产生纵向滚动条。 子图默认关闭滚轮缩放，鼠标位于图内时滚轮仍滚动列表；可勾选“滚轮缩放”开启较缓的缩放。该开关也适用于无参考诊断子图，图卡上的重置按钮可恢复视野。

## 验证工作台：套件、主题与验证项

用一个套件组织同一项目的验证，例如建立 `BFO` 套件，再按 EOS、MAE、交换响应、剪切等主题整理验证项。同一份参考数据可以加入多个套件；主题归属和显示名称分别保存在各自套件中。主题与四态分析中的样本分组相互独立。

打开套件先显示“总览”：按主题列出各模型已计算、失败、不支持及相对基准退化的验证项数量。不同物理量不会合并为一个总误差；“已计算”也不代表物性验收通过。总览读取已有评估摘要，不自动预测或加载全部曲线文件。

点击左侧主题查看验证项；双击某项打开曲线和数值详情。勾选框决定运行范围，可以跨主题保留；浏览、选中行和打开详情都不会改变勾选范围。“勾选当前视图”只增加当前可见项，“清空勾选”清除整个套件中的勾选。任务启动后固定当次模型与验证项，继续浏览或调整下一次勾选不会改动正在执行的任务。

导入文件夹时，可勾选“按来源文件夹建立主题”；已有套件也能用“按来源文件夹分组”整理尚未分组的项。“添加已有验证项”支持搜索名称和原始来源路径，并能恢复归档项，不需要重新复制数据或预测。分享包保留主题和套件内的显示名称。

在验证项列表选中行，再用右键菜单或“管理选中项”操作：可以改名、移动主题、编辑分析版本、从当前套件移除或归档。这里的行选择用于管理，复选框用于运行。删除主题会将成员移到“未分组”，不会删除验证项。

编辑分析会保存新版本，并替换当前套件中的对应项；其他套件仍引用原版本。旧数据快照及评估历史保留，新版本显示尚未评估，不沿用旧版本的精度。对选择了部分帧的 EOS 子组，编辑时保留 EOS 协议；需要其他分析类型时另建验证项，避免无意扩大到原始文件全部帧。

“从当前套件移除”只解除当前成员关系。“归档”保留快照和历史；被其他套件使用的项不能直接归档，应先从当前套件移除。软件不会通过这些操作删除原始文件。运行历史按当前主题列出已有评估记录及失败原因。

## 参考响应分析

在模型验证页导入参考数据，选择“参考响应 · 扫描 / 能差 / 组合”。软件会根据已有字段建议分析方式，保存前可修改分组字段、参考态和归一化方式。这里评估模型在给定结构上的响应；不会修改结构或代替模型弛豫。

- **参考扫描曲线**：选择一个扫描字段，可选第二坐标轴。体积、磁矩比例、角度和位移等均可使用。相对曲线统一减去参考曲线的最低点，不单独移动各模型的最低点；二维稀疏点按第二坐标分片显示。
- **状态能差**：按一个或多个字段分组，指定状态字段和每组唯一的参考态。状态字段可以组合，例如 `direction, plane, angle_deg`；部分状态分量缺失时用空值区分，但每个状态至少有一个值。参考态填写相应值，以逗号分隔，末尾空值可省略。
- **四态响应**：两个状态字段分别取 `-1/+1`，计算 `E++ + E-- - E+- - E-+`。同组须有且仅有四个状态，原子几何相同。
- **交叉响应**：两个状态字段分别取 `0/1`，计算 `E11 + E00 - E10 - E01`。也可在“有符号状态组合”中直接填写状态及系数；不会执行文本表达式。
- **分组精度统计**：分别统计各组的 E/F/V/MF 误差、有效标签分量和实际比较分量。缺失标签保持不可用；数据用途由用户明确声明为训练回归、开发验证或验证集，不根据文件名推断独立性。

保存前的预览会列出完整组、响应点数和排除原因。重复状态、缺少参考态或缺少四态端点时默认禁止导入；只有明确勾选“排除不完整或无效的组”后才排除相应组。结果页采用小图卡，数值按钮可以查看原始帧编号与组合系数、逐点误差、采样最低点和局部三点曲率，并导出 CSV。边界最低点不报告曲率。

能量可以按晶胞、全部原子或所选元素的原子数归一化，显示为 meV 或 μeV。应力和压力显示为 GPa；使用自定义参考字段时，换算系数必须将该字段直接转换到所选的最终显示单位。例如 `dft_pressure_kbar` 转换到 GPa 的系数为 `0.1`。磁力参考字段仅支持 `force_mag` 和 `mforce`。

需要从四态提取交换响应时，额外勾选“提取单位自旋双线性交换投影”，声明 `H = Σ eᵢᵀJᵢⱼeⱼ` 的正号及单位自旋约定，填写有序原子对字段、原子编号起点和相互作用重数。软件检查两个扰动是否独立、磁矩模长是否固定、其他磁矩是否不变；仅报告实际扰动方向上的有效投影。存在交换两个方向的配对数据时，同时给出对称部分及相应方向的 D 投影。它不自动补全未采样的张量分量，也不替用户判断周期镜像的键重数。

若分组或扫描信息只编码在名称中，可通过“导入分组元数据 CSV”补充映射。CSV 使用从 0 起的 `frame_index` 或唯一的 `frame_id` 关联原始帧，其他列定义标量分组或扫描字段。映射随分析方案保存，不修改 XYZ，也不允许覆盖结构、磁矩或参考标签。

批量导入可从加载菜单选择多个参考文件，或选择文件夹递归查找 XYZ/EXTXYZ。后台预览不运行预测；可以逐个检查配置，勾选有效文件后统一导入。所有所选文件先校验再登记。预览会提示本批数据中相同有序输入和相同几何的重叠数量，报告随数据来源保存；该检查不是全库、跨原子重排或独立盲测证明。

预测缓存绑定模型和数据 SHA-256、所选帧及计算环境；分析方案另外绑定分组、参考态、组合系数、归一化方式和版本。同一模型与数据使用不同分析方案时可复用预测；“重新计算”会绕过缓存。预测缓存位于库目录的 `cache/predictions/`，属于可重建缓存。分享包保存参考数据与分析设置，不导入预测结果。

固定磁态 EOS 现支持普通 NEP 和自旋模型，并检查不同体积点的输入磁序及磁矩模长保持一致。磁矩模长扫描应使用参考响应分析，而不套用体积 EOS 拟合。有限 q、场标记或极化参考字段不会自动变成长波周期、场下弛豫或极化预测；这些需要各自的计算方法及输入参数。

命令行可用 `nepkit-validate import data.xyz --name response --source DFT --analysis recipe.json` 导入同样的 JSON 分析设置。

## 存储位置

数据管理和模型验证共用一个**库目录**，默认在用户配置目录下：

- Windows：`C:\Users\<You>\AppData\Local\NepTrainKit\library\`
- macOS / Linux：`~/.config/NepTrainKit/library/`

库目录里有索引数据库 `library.db`、按内容哈希保存的模型与验证集快照（`objects/`）
和评估结果（`results/`）。数据库中只存相对路径，整个文件夹拷走即可备份或迁移。
设置环境变量 `NEPTRAINKIT_LIBRARY` 可以改用其他位置（集群或命令行常用）。

首次启动时，旧版的 `mlpman.db` 会被**复制**到库目录，原文件保留不动。

库目录只复制体积小、结果依赖的文件（`nep.txt`、验证集）。训练集等大文件只记录路径和
指纹；文件被移动或修改后会标记出来，不会自动复制你的训练数据。

库清理与快照、评估结果的发布和登记会协调执行，避免把正在登记的文件误删为孤立文件。
