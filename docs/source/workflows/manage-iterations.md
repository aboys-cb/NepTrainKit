# 组织多轮数据和模型版本

当同一体系已经经历多轮候选生成、DFT 和训练后，最容易丢失的不是文件，而是“这一轮为什么存在”。
这条流程把中间数据文件和 `Data Management` 记录结合起来，保证后续能回到来源。

## 每轮保留四个边界

建议每轮至少区分：

```text
candidate_pool.xyz
candidate_pool_clean.xyz
dft_labeled.xyz
train.xyz
```

- `candidate_pool.xyz`：生成卡片的原始输出，可能包含异常结构。
- `candidate_pool_clean.xyz`：完成几何和预测预筛后的候选池。
- `dft_labeled.xyz`：已经得到 DFT 标签的结构。
- `train.xyz`：真正进入本轮训练的数据，可能还包含历史数据。

不要用同一个文件名反复覆盖四个阶段。否则发现问题时无法判断是生成、清洗、DFT 还是合并阶段引入。

## 在 Data Management 中记录什么

以材料体系或研究目标建立 `Project`，每次正式训练建立一个 `Model(version)`。每个版本至少记录：

- 模型和训练结果目录；
- 本轮训练集路径；
- 新增结构的来源和数量；
- 删除或隔离了哪些异常结构；
- 本轮主要目标，例如 `surface`、`vacancy`、`magnetic` 或 `high-force`；
- 当前已知限制。

建议使用连续版本名，例如 `v001`、`v002`，不要把“final”“final2”“new-final”当成版本关系。

## 一轮结束时的检查

完成训练和误差复核后，再写版本记录。记录应能回答：

1. 这一轮相对上一轮增加了什么；
2. 哪些判断来自 DFT，哪些只来自 NEP 预测预筛；
3. 模型在哪些结构范围内做过检查；
4. 下一轮最明确的数据缺口是什么。

`Data Management` 只保存项目、路径、标签和备注，不会复制大体积训练数据。移动目录后必须更新记录，
也不能把数据库记录当成数据备份。
