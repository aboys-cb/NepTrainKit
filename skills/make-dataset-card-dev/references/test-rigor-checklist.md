# 卡片测试严谨性清单

本清单用于新建、重构和修复 Make Dataset 卡片。不要机械地给每张卡套全部测试；先根据卡片的公开契约选中适用风险，再证明用户可观察的行为。

写测试前先问：

> 如果这项承诺坏了，现在哪条断言会失败？

答不上来，就还没有覆盖。

## 1. 先列行为矩阵

至少列出：

- 每个公开模式和关键参数分支；
- 会争抢同一资源的参数组合，例如元素候选池、原子集合、输出预算、晶胞自由度；
- 默认值、边界值、非法值和禁用哨兵；
- 正交/非正交晶胞、全周期/混合 PBC 等适用几何；
- 新 JSON 与至少一个真实旧 JSON；
- 成功有输出、合法空输出、失败三类终态。

不要只逐参数单测。`auto/manual × 有效/无效晶胞`、两条规则共享同一候选池等交互，必须用真值表或参数化测试覆盖。

对于 `rules: list[dict]`、条件表或其他嵌套参数，行为矩阵必须继续展开内部判别字段，例如 `use × count_mode`；顶层 Params 字段出现过一次不等于内部所有模式已覆盖。

## 2. 证明物理和几何语义

operation 测试要断言卡片真正承诺改变或保持的对象：

- 输出数量、原子数、元素组成；
- 完整 `3×3` cell、体积、PBC；
- 笛卡尔或分数坐标、位移方向和幅值；
- 距离、角度、密度、应变、层或切面；
- magmom、group、sublattice 等数组；
- 过滤的保留/剔除集合；
- `Config_type` 追踪标签。

涉及方向、层、表面、层错、复制或应变时，至少加入一个非正交 cell；不能只检查 `cell[i, i]`。涉及 PBC 时加入一个混合 PBC，并检查周期边界附近原子的行为。若 UI 声称支持任意取向，测试必须使用非默认取向，而不是只测常用预设。

## 3. 审查默认值、哨兵和兼容性

对 `None`、`0`、空字符串、`False`、`auto_*` 等特殊值，直接断言其语义：

- 它是关闭限制、自动推导、使用默认上限，还是物理零值；
- 默认路径是否仍保留安全上下界；
- 自动模式对已有有效 cell 和无效 cell 分别做什么；
- 新配置往返后类型不漂移；
- 旧 JSON 缺少新字段时是否恢复旧行为，行为有意变化时是否明确迁移。

默认值测试不能只比较 dataclass；要运行 operation，证明默认输出语义。

## 4. 随机操作先定义合同，再扫种子

先选定并记录一种输出合同：

1. **严格数量**：合法参数必须得到目标数量，否则显式失败。
2. **尽力生成**：允许少于目标数量，但 UI、文档和返回状态必须明确“最多”。
3. **允许随机耗尽失败**：约束下可能零输出，必须给出确定、可行动的错误，不能空列表伪成功。

然后测试：

- 固定 seed 可复现；
- 输出的组成、几何和标签不变量；
- 共享资源、多规则、重试或拒绝采样存在时，做低成本多种子扫描。默认用至少 20 个 seed；若单次 operation 很重，缩小但保持同类约束的输入，或用可控 RNG/monkeypatch 构造最坏抽样路径；
- 确定性不可能的配置在采样前报错；
- 单次抽样不可行按合同重试或跳过，不能意外终止整卡；
- 重试耗尽按合同返回 partial 或失败，并有专门断言。

范围值会转换成有限的离散资源（候选原子、缺陷位点、输出预算等）时，固定加入以下四格：

| 输入 | 容量关系 | 必须证明 |
| --- | --- | --- |
| 固定值 | 可行 | 得到精确承诺的数量 |
| 固定值 | 不可行 | 确定性报错，不截断 |
| 随机范围 | 上界可行 | 至少 20 个 seed 都满足合同 |
| 随机范围 | 上界不可行 | 至少 20 个 seed 终态一致，并在第一次 RNG 调用前报错 |

先问“仅看参数和输入，能否知道这次请求可能超容量？”能知道就属于校验，不属于随机失败；测试应通过 monkeypatch RNG、调用独立 validation helper，或多种子一致终态证明校验顺序。

“20 个种子全部成功”只适用于严格数量合同；不要把它强加给明确允许随机耗尽的卡片。

## 5. 直接调用退化和非有限输入

按卡片适用范围选择：

- 0/1 原子、空数据集、空规则；
- 目标元素不存在、全部同元素；
- 无 cell、奇异 cell、非正交 cell、混合 PBC；
- NaN/Inf 坐标、cell 或参数；
- 数量恰好够、差一个、整除与不整除。

像真实调用方一样解包和使用返回值，不能只断言“不为 None”。成对 helper（PBC/非 PBC、共线/非共线）用同一组退化输入检查返回结构一致。

测试可观察分支，不把“每个源码 return 都有测试”当目标；重构后的实现细节不应导致无意义的测试重写。

## 6. 枚举运行终态和错误可见性

按 operation 合同分别断言：

- 成功且有输出：下游可继续，状态和数量正确；
- 合法空输出：过滤/筛选卡可以为空，但界面要显示空输出，不得冒充“生成成功”；
- 失败：错误可见，partial 是否保留按合同处理，下游不误运行。

禁止新增 `except Exception: pass`。确需降级时，用故障注入证明异常会冒泡，或用户/日志能看到原因。

## 7. 让 preview/summary 与正式运行共享语义

先声明 preview 类型：

- **精确预览**：数量、保留集合或失败结论应与 `run_*` 一致；
- **估算预览**：明确显示“理论/估算/最多”，测试误差边界或上限关系，不冒充正式结果。

两者应复用 operation 的校验和核心计算 helper，避免复制一套规则。

对随数据规模增长、包含批量循环、邻居搜索、PBC minimum-image 或两两距离的预览：

1. 用代表性输入做本地耗时 probe；约 100 ms 以上或明显随数据集增长时转后台。
2. UI 测试证明计算不在主线程执行。
3. 连续调参要防抖或合并，只应用最新请求结果。
4. 卡片关闭、输入清空和任务失败时，不回写过期结果，不销毁仍在运行的 `QThread`。

不要在共享 CI 上用很紧的绝对毫秒阈值制造 flaky；把真实性能数据作为交付证据，用线程、请求代次和最终状态断言固化交互合同。

## 8. 检查注册、查找、文档和翻译清单

- 动态遍历所有内置卡片，断言每张卡已注册、能实例化、拥有文档元数据和可解析的文档 URL。
- 不硬编码“当前共有 38 张卡”之类数量；新增卡片时，集合关系应自动发现遗漏。
- 检查查找弹窗的一句简述、`Add new card` 下拉项、分组、枚举和新增状态文案已翻译。
- 对每个下拉值，用控件的真实 `userData`/序列化值构造 Params，再直接调用 operation 对应分支；UI 往返测试和手写 operation 参数测试不能使用两套未比较的字符串。
- 文档 schema、Params 字段、运行时 `to_dict()` 保持一致。

## 9. 对比多条输出路径

当改动涉及 arrays/info、磁矩、group、sublattice、PBC 或导出时，让同一份输出至少走两条真实路径：

- 卡片直接导出；
- Card Group 或内存 handoff；
- Dataset Display 再保存。

比较最终字段集合、shape、dtype 和数值。只在改动触及共享输出合同或新增出口时要求此项，不给每个纯几何卡重复造昂贵集成测试。

## 10. 保持测试自身可靠

- 不向 `tests/data/`、仓库根目录或其他 tracked 路径写运行产物；使用 pytest tmp 目录并复制只读 fixture。
- 轮询明确终态，不用固定 sleep；CI 超时给标称耗时足够余量。
- 随机测试断言合同和不变量，不写逐坐标快照。
- 不依赖 NumPy/SciPy 某个版本的具体随机计数；除非该序列本身就是公开合同。
- 不用硬编码卡片总数、行号或无关 UI 文案维持测试。
