# Make Dataset 工作流 UI 契约

修改参数卡布局、卡片头、右侧检查器、卡片目录、分组/分叉或工作流库时读取本文件。普通 core operation 改动不需要加载这些细节。

## 1. 先区分参数卡与工作流容器

### 普通参数卡

- 继承 `MakeDataCard`，通过 `create_operation()` 连接 `StructureOperation`、`DatasetOperation` 或 `GeneratorOperation`。
- 用 `get_params()` / `set_params()` 维护 frozen Params dataclass。
- `setting_widget` 是可移动的参数编辑器：运行时会从卡片正文移到右侧 `WorkflowGuidancePanel`，切换选择或销毁时再安全归还。
- 不依赖 `setting_widget` 的原父对象、全局坐标或固定宽度；不要在重挂载后调用不属于同一父层级的 `mapFrom()`。

### 工作流容器

- `CardGroup`：所有启用子卡接收同一份输入，各自独立处理后立即合并；可再接一张合并后筛选卡。
- `WorkflowFork`：所有分支接收同一份输入，每条分支内部保持线性处理；输出保持独立，只有显式合并后才能连接共享下游卡片。
- 容器是编排节点，不要求伪造 Params、operation 或 `process_structure()`。
- 容器直接在画布编辑，并通过 `get_inspector_overview_text()` 向右侧检查器提供只读结构概览。

## 2. 右侧检查器中的参数表单

新卡片以右侧检查器为主要编辑环境，而不是按独立宽卡设计。

- 用 `InspectorSection` 分组相关参数，用 `CompactField` 形成标签在上、控件在下的字段。
- 用 `ResponsiveFormGrid` 在一列和两列之间重排；相关短字段可以并排，长说明、规则编辑器和多控件组合使用整行。
- 控件和字段 `minimumWidth` 应允许收缩，不设置迫使检查器横向滚动的固定宽度。
- 数值控件必须给文本、单位和步进按钮分别留出空间；默认主窗口尺寸下仍要完整显示整数和浮点数。
- 2-4 个短且固定的互斥选项使用 `SegmentedControl`；选项较长、动态生成或需要下拉说明时使用 `ComboBox`。
- `adapt_legacy_inspector_form()` 只用于兼容旧卡片；新增或实质重构卡片应直接采用共享紧凑组件。
- 模式切换后，不生效的字段隐藏或禁用；隐藏字段变化后 `ResponsiveFormGrid` 必须重新排布，不能留下空洞或重叠。

每张参数卡提供：

- `get_summary_text()`：当前关键配置或运行前数据摘要，简洁且可随控件变化刷新。
- `get_guidance_text()`：针对当前参数和输出风险的检查建议，不重复参数说明。

两者若随数据规模增长或约 100 ms 以上，使用共享后台预览机制，只应用最新请求并安全处理关闭。

## 3. 操作入口只保留一个归属

不要在卡片头、右侧检查器、全局控制台和左侧管理区重复同一动作。

| 动作 | 归属 |
|---|---|
| 启用/停用、类别、标题、运行状态、查看输出、结果导出、关闭 | 顶层卡片头 |
| 打开文档、卡片信息/贡献者、复制单卡 JSON | 右侧检查器右上角 |
| 新建卡片 | 全局控制台中的单一“新建卡片”入口 |
| 运行、停止 | 全局控制台直接可见 |
| 保存/另存为/重命名/复制工作流、粘贴工作流 JSON | 左侧工作流管理区 |
| 全局状态和后续扩展信息 | 工作台底部状态栏 |

分组或分叉中的子卡使用紧凑纵向卡片，不重复顶层结果操作；仍需保留可发现的选择、启用和移除交互。

添加第一张卡片即可形成未保存工作流，不恢复常驻“新建工作流”按钮；清空当前工作流使用左侧区域的标准新建快捷键。

## 4. Fluent 卡片目录

- `ConsoleWidget` 只提供一个“新建卡片”按钮，打开 `CardLibraryPopup`；不要恢复超长下拉菜单或单独的 Find Card 按钮。
- 弹窗按 `CardMetadata.group` 分类，支持本地化名称、类名、分组和简述搜索。
- 每张可发现卡片必须有名称、分组、简述和文档元数据；`discoverable = False` 的兼容类不显示。
- 分组图标表达真实语义，不用仅为装饰的随机图标。
- 悬停和键盘聚焦都要展示反馈及简述；Enter 可选择首个结果。
- 弹窗限制在可用屏幕范围内，内容过多时使用 Fluent 滚动条。

## 5. 分组、分叉和拖拽

- 新建卡片进入当前明确选中的容器或分支；没有目标时加入顶层工作流。
- 空分支可以被点击选中并接收下一张新卡；拖拽悬停也必须建立清晰目标。
- 分组/分叉展开后点击其他卡片，仍能重新选择、展开和继续拖入。
- 手动展开的容器必须能再次收回；折叠状态不能破坏子卡次序、选中态或参数编辑器归属。
- 组内、组间和顶层之间移动时，只能有一个父容器；信号连接、运行状态和序列化顺序同步更新。
- 立即合并组和永久分叉不能互换语义：前者合并每张子卡的输出，后者保持整条分支流水线独立。
- 停止操作传播到当前运行子卡；失败、部分失败、合法空输出和取消有明确终态，不把失败伪装为空成功。

## 6. 响应式工作台

- 普通卡片使用居中的可读最大宽度；分组和分叉可以更宽以容纳并行路径，但不无条件拉满画布。
- 默认主窗口尺寸下保留左侧工作流管理区和右侧检查器；不要通过隐藏任一侧栏来掩盖中间区域挤压。
- 中间画布优先压缩，参数检查器保持可用宽度且不出现横向滚动。
- 至少验证默认尺寸、宽屏、宽屏再缩回默认尺寸；检查卡片次序、分支布局、数值显示、滚动范围和当前选中卡。
- 视觉 probe 必须从真实 `MakeDataWidget` 或主程序入口进行；单独实例化控件的尺寸不能作为最终依据。

## 7. JSON 与工作流库

- 顶层工作流配置使用 `workflow_schema = 2`，普通卡继续保留 Params 与真实旧 key 的兼容读取。
- `CardGroup` 递归保存 `card_list` 和可选 `filter_card`。
- `WorkflowFork` 递归保存 `branches`，每条分支保留稳定 `id`、名称、启用状态和卡片顺序，同时保存显式合并状态。
- 加载旧 JSON 时补默认值，不静默改变原有物理参数或输出方式；无效或递归不支持的容器要明确失败。
- 工作流库只保存可复用配置，递归移除 `dataset`、`result_dataset`、`run_outcome`、运行时状态和耗时。
- 模板打开后先进入只读来源的“未修改预览”状态，不覆盖模板，也不立即标记为新建或未保存。首次修改参数、卡片或顺序后，才变为基于该模板的未保存工作流；工作流与单卡 JSON 的复制入口和提示文案必须明确区分。

## 8. 聚焦验证

涉及本文件范围时运行：

```bash
python skills/make-dataset-card-dev/scripts/run_card_checks.py --quick --ui
```

UI 模式至少覆盖：

- 所有内置参数卡在窄检查器中无横向滚动；
- 共享紧凑控件、数值可见性和模式联动；
- Fluent 卡片目录的分类、搜索、键盘/鼠标选择和翻译；
- 分组/分叉的插入目标、拖拽、展开收起、运行停止、输出语义和递归 JSON；
- 工作流库不保存运行数据，模板按副本打开；
- 模板预览在未修改时不触发未保存提示，首次修改后才进入 dirty 状态；
- 默认尺寸与宽屏往返后布局稳定。
