# Make Dataset Workflow

1. Start from the intended comparison or dataset gap. Establish what varies, what stays fixed, which reference structures must survive, and the final budget. Inspect supplied files and retain confirmed choices. Ask one consequential question per turn in materials terms. Recommend a default for each applicable choice and use it when skipped or accepted. Ask for missing inputs that determine feasibility.
2. Work backward from the desired outputs. Look up candidate operations in the [card catalog](../../docs/source/module/make-dataset-cards/index.md) and read the relevant contracts. Check what each stage requires, changes, preserves, and emits, including reference labels. Add missing prerequisites, such as a seed generator, surface construction, site labels, realized alloy occupancy, or reference moments. Generators create new seeds and dataset filters act on the full pool. Prefer a dedicated card when it preserves the requested path or controls. Ask before approximating unsupported requirements.
3. Ask about supercell expansion for periodic seeds. Default to one `SuperCellCard` output when expansion is suitable, before the first operation that needs the larger periodic cell. Size it for the actual constraint, such as integer stoichiometry, defect separation, or magnetic periodicity, and report the atom count against budget. Keep vacuum and nonperiodic axes at one repeat. Use the supplied cell if it meets the target. For defects or spin sampling, read [defect and magnetic workflows](references/defects-and-magnetism.md).
4. Share the prepared parent for matched comparisons. Use serial cards when changes must coexist in each output, `CardGroup` to pool independent operations on the same input, and `WorkflowFork` for separate pipelines or exports. Merge explicitly before a shared downstream card. For combined lattice and atomic perturbation, apply `PerturbCard` after deformation. For broad coverage, pool independent normal-strain and shear paths first. Confirm axes, convention, ranges, and whether to retain pure controls.
5. Budget the candidate pool before setting per-card counts. Add parallel yields and multiply serial yields according to each contract. Check bounds, duplicate reference states, and complete comparison groups. Recommend batch generation followed by Show NEP review, selection, and subset export. Ask whether to use it and identify the output, selection criteria, and budget. Use the Make Dataset FPS card only on request. Descriptor selection needs a suitable NEP model.
6. Show a plain-text flowchart with inputs, card order, branches, merges, key settings and units, default choices, counts, and where selection and export happen. Identify the upstream stage when extending a workflow. Mark estimates. Wait for confirmation before generating JSON. Keep Show NEP steps in the diagram and handoff. Serialize the Make Dataset configuration.
7. Follow a real export from the target version. Check the [card registry](../../src/NepTrainKit/core/workflow.py), card serializers, and parameter docs. Write `workflow_schema: 2` and `cards` using native card and container formats. Validate the configuration and, when possible, import and re-export it in the GUI to compare cards and effective settings. Check representative outputs against the agreed invariants when inputs are available. `preview` checks parsing only. Deliver the file, import instructions, and validation scope.
